# Homepage surface brief

Scope: `/` marketing homepage. Mode: Persuade. Audience: AI engineers first, a short section for the approving infra/security lead. Action: join waitlist (mailto fallback, no fake confirmation). Proof: a refused write shown working; the three-tool contract; the two enforcement layers; hosted and self-hosted setup.

## Direction contract

THESIS: The path through the boundary. The page draws the real mechanism: an agent's query travels down a rail, crosses the QueryIO band where each check passes or refuses it, and only then reaches a read-only replica. Replaces the earlier teller-window metaphor (brass, glass, slips), which made visitors decode a metaphor before the product.

OWN-WORLD: Ink on near-white paper. Green means QueryIO (boundary band, passed checks, primary action). Vermilion means refused. Schibsted Grotesk for reading, Geist Mono for machine text only. No cards, no badges, no terminal chrome.

STORY: See a write refused and a read answered (hero), understand the risk of a connection string, learn the three-tool contract, see why a read-only role alone is not enough, see hosted or self-hosted setup, join the waitlist.

FIRST VIEWPORT: Headline "Your agents can read production. They can't change it." with a lede that defines MCP once, email + button under it. Right: the path diagram defaulting to "Try a write".
